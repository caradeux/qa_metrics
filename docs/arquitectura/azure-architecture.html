03

Ruta de la petición

Cómo viaja una solicitud del analista, desde el navegador hasta la base de datos y las integraciones externas.

1

Resolución y TLS

Azure DNS resuelve el dominio al Application Gateway, que termina el certificado TLS (Managed Certificate). Entra por el puerto 443.

2

Balanceo por host

El Application Gateway enruta qa-metrics… a Container Apps — Web y api.qa-metrics… a Container Apps — API.

3

Renderizado y lógica

Web (Next.js) hace SSR y llama a la API (Express); ambos leen/escriben en Postgres vía Prisma (pg).

4

Persistencia

Consultas a PostgreSQL Flexible Server en subred delegada por el puerto 5432 (Private Link). Sin exposición pública.

5

Generación de reportes

La API produce PPTX / Excel / PDF con gráficos server-side (picos de CPU puntuales) y los entrega o los guarda en Blob Storage.

6

Integraciones salientes

Correo vía Resend y carga de horas a FlowPilot salen a internet por el NAT Gateway.

Justificación por componente

Por qué cada servicio entra en la arquitectura, por qué se eligió frente a sus alternativas, y cómo se ancla en el código real de la aplicación (monorepo turbo: apps/web, apps/api, packages/database).

ACA
Container Apps — Web
Cómputo · Frontend Next.js 16
Por qué se necesita
El front es Next.js 16 con SSR y next-auth: necesita un runtime Node siempre disponible que ejecute el contenedor de apps/web/Dockerfile y renderice por request.
Por qué este servicio
Container Apps corre la misma imagen Docker que hoy usan en Coolify, sin administrar servidores. Trae ingress Envoy + TLS gestionado y escalado por reglas (KEDA) de fábrica.
Alternativas descartadas
App Service: PaaS válido pero con escalado menos granular y sin escala a cero. AKS: sobredimensionado en operación. VM: gestionar SO/parches.
Dimensionamiento
0.5 vCPU / 1 GiB, 2 réplicas para HA tras el ingress.
ACA
Container Apps — API
Cómputo · Backend Express 5
Por qué se necesita
La API (apps/api) hace auth JWT/bcrypt y genera reportes pesados: PPTX (pptxgenjs), Excel (exceljs), PDF (jspdf) y gráficos server-side con chartjs-node-canvas (render en canvas nativo, intensivo en CPU/memoria).
Por qué este servicio
App separada del web dentro del mismo Environment: se escala/dimensiona sola y un reporte pesado no degrada la navegación. KEDA escala por concurrencia HTTP.
Alternativas descartadas
Azure Functions: los reportes con canvas y libs nativas exceden el modelo serverless cómodo. Un solo contenedor web+api: acopla el escalado.
Dimensionamiento
1 vCPU / 2 GiB; picos de reporte puntuales → 2 réplicas absorben concurrencia.
PG
PostgreSQL Flexible Server 16
Base de datos
Por qué se necesita
El dominio es 100% relacional: 24 modelos Prisma con FKs (Users, Testers, Projects, TestCycles, UserStory, DailyRecord, Flowpilot*, Automation*…). El motor actual ya es Postgres 16.
Por qué este servicio
Flexible Server da backups, parcheo y HA zonal opcional, e integración con la VNet por subred delegada + Private Link. Sobre él corre prisma migrate deploy, igual que hoy.
Alternativas descartadas
Postgres en contenedor: gestionar almacenamiento y backups a mano. Cosmos DB: no relacional. Single Server: en retirada (legacy).
Dimensionamiento
B2s (Burstable, costo-eficiente) + 32 GB; zona redundante solo en Alta disponibilidad.
AGW
Application Gateway
Red · Ingreso L7 + WAF
Por qué se necesita
Punto de entrada HTTPS único con enrutado por host (qa-metrics… → web, api.qa-metrics… → api), terminación TLS y, opcionalmente, WAF delante de la app.
Por qué este servicio
Es capa 7 con WAF integrado (OWASP). Nota: Container Apps ya trae ingress propio, por lo que el App Gateway es opcional y se añade cuando se quiere WAF/L7 central o ingress privado.
Alternativas descartadas
Front Door: pensado para global/multi-región y CDN, de más para una app interna. Load Balancer: es L4, no rutea por host. Solo el ingress de ACA: usado en el escenario mínimo.
Dimensionamiento
Standard_v2 (o WAF_v2 en Alta disponibilidad) · 2 backends.
NAT
NAT Gateway
Red · Egress
Por qué se necesita
Las réplicas corren en subred privada pero deben salir a internet para enviar correo por Resend y sincronizar horas con FlowPilot (flowpilot.biz).
Por qué este servicio
Da una IP de salida estática — útil si FlowPilot exige lista blanca de IP — y egress gestionado de alta disponibilidad.
Alternativas descartadas
En el escenario mínimo se usa el egress gestionado del Environment de Container Apps (sin IP fija ni costo del NAT).
Dimensionamiento
1× (2 zonas en Alta disponibilidad).
BLOB
Blob Storage
Almacenamiento de objetos
Por qué se necesita
Hoy los uploads (multer) se parsean en memoria y los reportes se generan al vuelo. Para retener evidencias y reportes (auditoría, re-descarga) hace falta almacenamiento duradero fuera del disco efímero.
Por qué este servicio
Barato y duradero (LRS/ZRS), con SAS tokens para descargas directas sin pasar por la API.
Alternativas descartadas
Azure Files (SMB): innecesario para objetos. Binarios en Postgres: infla la DB y los backups.
Dimensionamiento
~10 GB Hot LRS; lifecycle a Cool para reportes antiguos.
ACR
Container Registry
Cómputo · Registro
Por qué se necesita
Container Apps necesita un registro desde donde traer las imágenes; hoy se construyen dos imágenes (apps/web/Dockerfile, apps/api/Dockerfile).
Por qué este servicio
Registro privado integrado con Managed Identity: Container Apps hace el pull sin credenciales almacenadas.
Alternativas descartadas
Docker Hub: público, con rate limits y credenciales que gestionar.
Dimensionamiento
Basic · ~2 GB de imágenes.
KV
Key Vault
Seguridad · Secretos
Por qué se necesita
La app maneja secretos reales: JWT_SECRET, JWT_REFRESH_SECRET, ENCRYPTION_KEY (que cifra las credenciales de FlowPilot del usuario) y DATABASE_URL.
Por qué este servicio
Container Apps referencia los secretos vía Managed Identity, con cifrado en HSM, rotación y auditoría de acceso centralizadas.
Alternativas descartadas
Secrets nativos de Container Apps: más simples, pero sin rotación, HSM ni auditoría central. App Configuration: para config, no para secretos sensibles.
Dimensionamiento
Standard · ~4 secretos. (El descubrimiento de FlowPilot dejó un password de QA a rotar.)
MON
Azure Monitor + Log Analytics
Gestión · Observabilidad
Por qué se necesita
La API loguea con pino; se necesita centralizar logs de contenedores, métricas (CPU/mem, réplicas, conexiones a PG) y alertas (fallo de sync a FlowPilot, CPU alta en reportes).
Por qué este servicio
El Environment de Container Apps envía logs a Log Analytics de forma nativa; Application Insights añade trazas/APM del runtime Node sin agente extra.
Alternativas descartadas
Datadog/Grafana Cloud: solo si ya existe observabilidad corporativa estandarizada (costo adicional).
Dimensionamiento
Workspace + App Insights + ~5 alertas.
DNS
Azure DNS + Managed Cert
Red · DNS y TLS
Por qué se necesita
Los dominios ya en uso —qa-metrics.inovabiz.com y api.qa-metrics.inovabiz.com— deben resolver al ingress, con TLS válido (las cookies Secure exigen HTTPS).
Por qué este servicio
El Managed Certificate de Container Apps/App Gateway emite y renueva TLS gratis y automáticamente para dominios propios; Azure DNS integra los registros.
Alternativas descartadas
Si el DNS de inovabiz.com vive en otro proveedor, se delega el subdominio o se usan CNAME; el certificado gestionado sigue aplicando.
Dimensionamiento
1 zona + certificados gestionados.
VNet
Virtual Network
Red · Aislamiento
Por qué se necesita
Aislar la aplicación: subredes públicas (App Gateway, NAT) y privadas (Environment de Container Apps y PostgreSQL), de modo que la base nunca sea accesible desde internet.
Por qué este servicio
Postura de seguridad por defecto con NSG por capa y Private Link a PostgreSQL; el Environment de Container Apps se integra en una subred de infraestructura dedicada.
Alternativas descartadas
Servicios con endpoints públicos: expondría la DB y el cómputo; inaceptable incluso para uso interno.
Dimensionamiento
2 zonas · subred de infra para ACA (mín. /23) + subred delegada para PG + subred del App Gateway.

08

Supuestos y exclusiones

Base sobre la que se construyen las cifras. Cualquier cambio impacta el costo.

  • Región base East US. Se muestra Brazil South como referencia para Chile; elegir región es decisión de arquitectura por latencia/compliance (Chile Central es opción emergente).
  • Precios On-Demand, sin compromisos. No incluyen Reserved Instances, Savings Plans ni descuentos de contrato Enterprise Agreement.
  • No incluye impuestos (IVA), soporte Azure (Standard ~$100/mes), ni costos de migración inicial.
  • Resend y FlowPilot son SaaS externos: su costo es aparte (Resend ~$0–20/mes). Opción: migrar correo a Azure Communication Services (Email).
  • Sin colas, cron ni workers en el código actual: los reportes se generan síncronos on-demand. No se presupuestan Service Bus/Functions.
  • Almacenamiento persistente hoy es mínimo: los uploads se parsean en memoria. Blob Storage se incorpora como buena práctica para retener evidencias/reportes.
  • HA de datos opcional: el escenario Recomendado usa PostgreSQL sin zona redundante con backups; la HA zonal se reserva para el escenario de Alta disponibilidad.
  • Tráfico modesto: herramienta interna sin exposición pública masiva; el WAF de Application Gateway solo se presupuesta en el escenario de Alta disponibilidad.

El MCP solicitado en el pedido original es específico de AWS. Para Azure, el equivalente son la Azure Retail Prices API y el Azure Pricing Calculator.

Cómo obtener las cifras exactas de Azure

Estos montos provienen de tarifas públicas de Azure (On-Demand, East US). Para valores exactos, verificados por región y SKU, hay dos vías:

  1. Azure Retail Prices API (pública, sin auth): https://prices.azure.com/api/retail/prices — filtrable por armRegionName, serviceName y skuName.
  2. Azure Pricing Calculator (azure.microsoft.com/pricing/calculator) para armar el presupuesto formal y exportarlo.
  3. Existen servidores MCP comunitarios de Azure pricing/retail que envuelven esa API; conectando uno se regenera la tabla del punto 06 con valores en vivo.

Dime si quieres que consulte la Retail Prices API directamente y recalcule cada línea para East US y Brazil South.
